# Stage 10 mega-boss: 3D pipeline (prototype)

A prototype that turns Rex's Meshy AI base mesh into a game-ready boss. **Not loaded by the game.** Nothing in `js/`, `index.html`, the APK or GitHub Pages uses these files yet.

Results and screenshots: [REPORT.md](REPORT.md).

## Files
| Path | What |
|---|---|
| `src/megaboss_meshy_original.glb` | Rex's Meshy 6 Lite GLB, **unchanged** (read-only; SHA-256 in `.sha256`, checked on every build) |
| `rig_src.json` | Hand-authored rig in game units: strip paths (top-down x,z), 7 weapon-bay markers, LOD targets |
| `build.cjs` | Turns the model to the game frame → 2 LODs (meshoptimizer) → hard-edge normals → engine anchors, strips, markers → `out/megaboss_{hq,smooth}.glb`, `out/rig.json`, `out/build_report.json` |
| `validate.cjs` | Asserting validator (exit 1 on any failure). Checks: glTF validator; outline overlap in 6 views; per-region overlap, missing pixels and height error (mean/p95/max); the exported quantized GLB as the r128 loader reads it (watertight, manifold, normals, outward winding, strips, engine and marker anchors); look-layer render and draw budget; nose direction → `out/validation.json`, `.log` |
| `viewer/` | Standalone three.js r128 viewer (`index.html`) and the enhancement layer `megaboss_fx.js` |
| `bundle.cjs` | One-file offline viewer for the phone → `out/megaboss_viewer.html` (not committed, about 2 MB) |
| `game_scene.cjs` | Boots the real game headless (S22 size and DPR) and flies Stage 10 with a seeded workload. Adds the boss from the test only. Measures repeated A/B runs, fixed-frame cost, first-load hitch, and load/unload and quality-switch resource checks. Asserts, exit 1 on failure → `out/game_scene.json`, `.log` |
| `capture.cjs` | Normal-speed motion capture on a virtual 30 fps clock → `out/capture/*.mp4` |
| `lint_glsl.cjs` | Rejects `smoothstep` calls with edge0 ≥ edge1 (undefined in GLSL) |
| `fixture.cjs` | Deliberately broken GLB; `npm run test:negative` proves validation fails on it |
| `shots.cjs`, `lab/` | Headless screenshots and render masks |
| `review/` | Screenshots for review |

Run (needs Node 22; Chromium comes from `/opt/pw-browsers` or Playwright):
```
cd tools/boss3d && npm i && npm run all
```

## Conventions
- **Game frame:** +X = screen right, **+Z = nose = screen down (toward the player)**, +Y = up. Units are Skyfire world units (K=0.1, so 1 unit = 10 logic px). The wingspan is 30 units (300 px of the 400 px lane) and the length is 36.5.
- The Meshy model faces −X; `build.cjs` turns it +90° about Y. The test checks the nose against the real `fitCamera()` setup: the nose lands at screen y +0.37 and the engines at −0.36.
- The ship's **left = +X** (it faces +Z), so `wb_*_L` markers appear on the right of the screen.
- GLB nodes: `hull`, `strip_red`, `strip_violet` (+ `glow_red`, `glow_violet` in HQ), empty nodes `eng_L/C/R` (extras: radius, dir) and `wb_*` (extras: bay, side, deploy direction, hidden).
- Mesh compression: `KHR_mesh_quantization`, which the r128 GLTFLoader supports. No Draco or meshopt decoder is needed.
- ⚠️ **three.js r128 returns raw integers when JavaScript reads quantized attributes** (`fromBufferAttribute`/`getX` don't de-normalize; the GPU path is correct). Any CPU-side use (merging, raycasts, hit tests, bounds) must de-normalize, as `megaboss_fx.js` `rd()` and `lab.html` `deq()` do. Game code must never raycast the raw quantized mesh.
